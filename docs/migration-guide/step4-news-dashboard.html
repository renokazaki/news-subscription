4-1. News モデル Rails

rails generate model News user:references title:string text:text url:string tag:string published_at:datetime
rails db:migrate
backend/app/models/news.rb
class News < ApplicationRecord
  belongs_to :user

  validates :title, :url, presence: true

  scope :by_date, ->(date) { where('DATE(published_at) = ?', date) if date.present? }
  scope :by_tag, ->(tag) { where(tag: tag) if tag.present? }
  scope :recent, -> { order(published_at: :desc) }
end
scope はActiveRecordのクエリをメソッドチェーンで組み合わせ可能にする仕組み。条件付きscope（if date.present?）は、パラメータがない時はそのscopeを無視してくれるので、コントローラー側で条件分岐を書く必要がない。

News.recent.by_date('2024-01-01').by_tag('React') のようにチェーンでき、SQL発行は1回だけ。各scopeが独立しているのでテストも容易。
テーブル名が news（不可算名詞）のため、Railsの自動命名規則と微妙にズレる場合がある。rails generate model News で生成した場合は問題ないが、手動で作る場合は self.table_name = 'news' をモデルに明記する。

4-2. News コントローラー Rails

backend/app/controllers/api/v1/news_controller.rb
module Api
  module V1
    class NewsController < ApplicationController
      before_action :authenticate_user!

      def index
        news = current_user.news
                  .recent
                  .by_date(params[:date])
                  .by_tag(params[:tag])

        render json: news.map { |n| news_summary(n) }
      end

      def show
        news_item = current_user.news.find(params[:id])
        render json: news_detail(news_item)
      end

      private

      def news_summary(news)
        {
          id: news.id,
          title: news.title,
          tag: news.tag,
          published_at: news.published_at,
          url: news.url
        }
      end

      def news_detail(news)
        {
          id: news.id,
          title: news.title,
          text: news.text,
          tag: news.tag,
          url: news.url,
          published_at: news.published_at
        }
      end
    end
  end
end
indexとshowでレスポンス形式を分ける理由: 一覧表示では text（要約本文）は不要。大量のニュースを一覧取得する際にテキスト全文を含めるとレスポンスサイズが肥大化し、パフォーマンスが悪化する。詳細画面で初めて全文を返す設計。
フィルタリングをサーバーサイドにする理由: 旧実装ではクライアントで全件取得してからJSでフィルタしていた。データ量が少ないうちは問題ないが、ニュースが数百件になるとフロントのメモリと初回ロード時間が問題になる。DBのWHERE句は数万件でも高速に動作する。

4-6. フロントエンド: useNews フック React

Step 3 と同じく、手動パターンとOpenAPIパターンの両方を示す。News APIはクエリパラメータ（フィルタ）を持つ点がInterestとの違い。

手動パターン

まず型定義を手書きする:

frontend/src/types/news.ts
export type NewsSummary = {
  id: number;
  title: string;
  tag: string;
  published_at: string;
  url: string;
};

export type NewsDetail = NewsSummary & {
  text: string;
};
frontend/src/hooks/useNews.ts
import { useQuery } from '@tanstack/react-query';
import { api } from '@/lib/api';
import type { NewsSummary, NewsDetail } from '@/types/news';

// ① 一覧取得（フィルタ付き）
export const useNewsList = (filters?: { date?: string; tag?: string }) => {
  // クエリパラメータを手動で組み立て
  const params = new URLSearchParams();
  if (filters?.date) params.set('date', filters.date);
  if (filters?.tag) params.set('tag', filters.tag);
  const query = params.toString();

  return useQuery({
    // フィルタが変わるとqueryKeyが変わり、自動再フェッチされる
    queryKey: ['news', filters],
    queryFn: () => api<NewsSummary[]>(`/news${query ? `?${query}` : ''}`),
  });
};

// ② 詳細取得
export const useNewsDetail = (id: number) => {
  return useQuery({
    queryKey: ['news', id],
    queryFn: () => api<NewsDetail>(`/news/${id}`),
  });
};
queryKey にフィルタを含める理由:
queryKey: ['news', filters] とすることで、フィルタが変わるたびに異なるキャッシュエントリになる。{ tag: 'React' } と { tag: 'Rails' } は別のキャッシュとして保持されるため、タグを切り替えたときに前回のデータが即座に表示される（キャッシュヒット）。
URLSearchParams の手動組み立てが必要: undefined のパラメータを除外する処理や、URLエンコードを自分で行う必要がある。パラメータが増えるとボイラープレートも増える。
OpenAPIパターン

型定義は不要（自動生成済み）。フックもシンプル:

frontend/src/hooks/useNews.ts
import $api from '@/lib/$api';

// ① 一覧取得（フィルタ付き）
export const useNewsList = (filters?: { date?: string; tag?: string }) => {
  return $api.useQuery('get', '/api/v1/news', {
    params: { query: filters },
  });
};

// ② 詳細取得
export const useNewsDetail = (id: number) => {
  return $api.useQuery('get', '/api/v1/news/{id}', {
    params: { path: { id } },
  });
};
クエリパラメータも型安全:
params.query に渡せるプロパティは date?: string と tag?: string だけ。存在しないパラメータ名（category など）を書くとコンパイルエラーになる。

undefined の値は自動的にURLから除外される。URLSearchParamsの手動組み立ては不要。queryKeyもパス+パラメータから自動生成される。

queryKey の比較

手動パターン OpenAPIパターン
一覧（フィルタなし） ['news', undefined] ['get', '/api/v1/news', { params: { query: undefined } }]
一覧（タグフィルタ） ['news', { tag: 'React' }] ['get', '/api/v1/news', { params: { query: { tag: 'React' } } }]
詳細 ['news', 42] ['get', '/api/v1/news/{id}', { params: { path: { id: 42 } } }]
どちらもフィルタが変わればqueryKeyが変わり、TanStack Queryが自動で再フェッチする仕組みは同じ。OpenAPIパターンではqueryKeyの設計を自分で考える必要がない。

4-7. フロントエンド: フィルタ状態の管理（Jotai） React

フィルタUI状態（日付・タグ）は Jotai で管理する。この部分は両パターン共通。

frontend/src/store/filters.ts
import { atom } from 'jotai';

export const selectedDateAtom = atom<string | undefined>(undefined);
export const selectedTagAtom = atom<string | undefined>(undefined);
なぜ Jotai を使うのか:
  • TanStack Query = サーバー状態（APIレスポンス）の管理
  • Jotai = UIローカル状態（フィルタ選択、モーダルの開閉など）の管理
フィルタは「ユーザーがUIで選んだ値」であってサーバーから取得するデータではない。2つのライブラリで責務を分ける。

データフロー: Jotaiのatomが変わる → useNewsList のフィルタ引数が変わる → queryKeyが変わる → TanStack Query が自動再フェッチ。明示的に「再取得」ロジックを書く必要がない。

4-8. フロントエンド: UIコンポーネント React

NewsFilters（フィルタUI）

タグフィルタ（ユーザーのInterestから取得）と日付フィルタを提供する。

frontend/src/components/news/NewsFilters.tsx
import { useAtom } from 'jotai';
import { selectedDateAtom, selectedTagAtom } from '@/store/filters';
import { useInterests } from '@/hooks/useInterests';
import { Button } from '@/components/ui/button';
import { Input } from '@/components/ui/input';
import { Label } from '@/components/ui/label';

export function NewsFilters() {
  const { data: interests } = useInterests();
  const [selectedTag, setSelectedTag] = useAtom(selectedTagAtom);
  const [selectedDate, setSelectedDate] = useAtom(selectedDateAtom);

  return (
    <div className="space-y-4">
      {/* タグフィルタ */}
      <div>
        <Label className="text-sm text-muted-foreground">タグで絞り込み</Label>
        <div className="mt-1 flex flex-wrap gap-2">
          <Button
            variant={selectedTag === undefined ? 'default' : 'outline'}
            size="sm"
            onClick={() => setSelectedTag(undefined)}
          >
            すべて
          </Button>
          {interests?.map((interest) => (
            <Button
              key={interest.keyword}
              variant={selectedTag === interest.keyword ? 'default' : 'outline'}
              size="sm"
              onClick={() => setSelectedTag(interest.keyword)}
            >
              {interest.keyword}
            </Button>
          ))}
        </div>
      </div>

      {/* 日付フィルタ */}
      <div className="flex items-center gap-2">
        <Label htmlFor="date-filter" className="text-sm text-muted-foreground">
          日付で絞り込み
        </Label>
        <Input
          id="date-filter"
          type="date"
          className="w-auto"
          value={selectedDate || ''}
          onChange={(e) => setSelectedDate(e.target.value || undefined)}
        />
        {selectedDate && (
          <Button variant="ghost" size="sm" onClick={() => setSelectedDate(undefined)}>
            クリア
          </Button>
        )}
      </div>
    </div>
  );
}
Interest一覧をタグフィルタに再利用: ユーザーが登録したInterest（React, Rails, AWSなど）がそのままタグフィルタのボタンになる。Interest CRUDで追加/削除するとフィルタボタンも自動で同期される（TanStack Queryのキャッシュが共有されるため）。

NewsList（ニュース一覧）

frontend/src/components/news/NewsList.tsx
import { useAtom } from 'jotai';
import { selectedDateAtom, selectedTagAtom } from '@/store/filters';
import { useNewsList } from '@/hooks/useNews';
import { Card, CardContent, CardHeader, CardTitle } from '@/components/ui/card';

export function NewsList() {
  const [selectedDate] = useAtom(selectedDateAtom);
  const [selectedTag] = useAtom(selectedTagAtom);
  const { data: news, isLoading } = useNewsList({
    date: selectedDate,
    tag: selectedTag,
  });

  if (isLoading) {
    return <p className="text-sm text-muted-foreground">読み込み中...</p>;
  }

  if (!news || news.length === 0) {
    return <p className="text-sm text-muted-foreground">ニュースがありません</p>;
  }

  return (
    <div className="space-y-3">
      {news.map((item) => (
        <Card key={item.id}>
          <CardHeader className="pb-2">
            <div className="flex items-center justify-between">
              <CardTitle className="text-base">
                <a href={item.url} target="_blank" rel="noopener noreferrer"
                   className="hover:underline">
                  {item.title}
                </a>
              </CardTitle>
              <span className="rounded bg-muted px-2 py-0.5 text-xs">
                {item.tag}
              </span>
            </div>
          </CardHeader>
          <CardContent className="pt-0">
            <p className="text-xs text-muted-foreground">
              {new Date(item.published_at).toLocaleDateString('ja-JP')}
            </p>
          </CardContent>
        </Card>
      ))}
    </div>
  );
}
