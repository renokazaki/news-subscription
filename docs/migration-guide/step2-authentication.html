Step 2: 認証システム（Devise）

所要時間: 1〜2日 | Devise + カスタムトークン認証でAPI認証を構築

このStepのゴール

ユーザーがサインアップ・ログイン・ログアウトでき、認証済みのリクエストのみがAPIにアクセスできる状態を構築する。フロントエンドでは認証状態に応じたルーティングガードが機能する。

2-1. Deviseの設計判断 Rails

DeviseはRails定番の認証gemだが、本来はブラウザ向け（Cookie/セッション前提）に設計されている。API-onlyモードではセッションが使えないため、トークンベースの認証を自前で実装する必要がある。

選択肢と判断

  • devise_token_auth: Devise拡張gem。便利だがメンテナンス状況が不安定
  • devise-jwt: JWT統合。シンプルだがトークン失効の管理が複雑
  • Devise + 自前トークン管理: 最もシンプルで理解しやすい。今回はこれを採用
自前トークンにする理由: Deviseのユーザー管理（パスワードハッシュ、バリデーション、モジュール構成）は使いつつ、トークン発行・検証だけを薄くカスタム実装する。JWTのような複雑なライフサイクル管理が不要なシンプルなアプリではこれが最も保守しやすい。

Devise設定の調整

backend/config/initializers/devise.rb（変更箇所のみ）
# API-onlyなのでナビゲーション系の設定を無効化
config.navigational_formats = []

# メーラーの送信元（パスワードリセット等で使う場合）

navigational_formats = [] が重要。デフォルトでは認証失敗時にHTMLリダイレクトしようとするが、APIでは常にJSONレスポンスを返したい。空配列にすることで「HTMLフォーマットへのリダイレクト」を無効化し、401ステータスコードが返るようになる。

authentication_token カラム: ログイン成功時にランダムトークンを生成し、このカラムに保存する。以降のAPIリクエストでは Authorization: Bearer <token> ヘッダーでこのトークンを送信し、ユーザーを特定する。セッション不要のステートレス認証になる。 
rails db:migrate

Userモデルの実装

backend/app/models/user.rb
class User < ApplicationRecord
  devise :database_authenticatable, :registerable, :validatable

  has_many :interests, dependent: :destroy
  has_many :news, dependent: :destroy

  validates :display_name, presence: true

  before_create :generate_authentication_token

  private

  def generate_authentication_token
    loop do
      self.authentication_token = SecureRandom.hex(32)
      break unless User.exists?(authentication_token: authentication_token)
    end
  end
end
SecureRandom.hex(32) で64文字のランダム文字列を生成。loop でユニーク性を保証している。暗号学的に安全な乱数生成器を使うので、トークンの推測は事実上不可能。

:validatable モジュールはメールのフォーマット検証とパスワード長の検証を自動で追加する。自分で validates :email を書く必要がない。

2-4. 認証コントローラー Rails

ベースコントローラーに認証メソッドを追加

backend/app/controllers/application_controller.rb
class ApplicationController < ActionController::API
  private

  def authenticate_user!
    token = request.headers['Authorization']&.split(' ')&.last
    @current_user = User.find_by(authentication_token: token)

    render json: { error: 'Unauthorized' }, status: :unauthorized unless @current_user
  end

  def current_user
    @current_user
  end
end
request.headers['Authorization'] からBearerトークンを取り出す。&.split(' ')&.last は安全なnilチェーン（Authorization ヘッダーが無い場合にnilを返す）。トークンからユーザーをDB検索し、見つからなければ401を返す。

この authenticate_user! を before_action で各コントローラーに適用することで、認証必須のエンドポイントを作る。

登録コントローラー

mkdir -p app/controllers/api/v1/auth
backend/app/controllers/api/v1/auth/registrations_controller.rb
module Api
  module V1
    module Auth
      class RegistrationsController < ApplicationController
        def create
          user = User.new(sign_up_params)

          if user.save
            render json: {
              user: user_response(user),
              token: user.authentication_token
            }, status: :created
          else
            render json: { errors: user.errors.full_messages }, status: :unprocessable_entity
          end
        end

        private

        def sign_up_params
          params.require(:user).permit(:email, :password, :password_confirmation, :display_name)
        end

        def user_response(user)
          {
            id: user.id,
            email: user.email,
            display_name: user.display_name,
            profile_image: user.profile_image
          }
        end
      end
    end
  end
end
登録成功時にトークンをレスポンスに含めることで、ユーザーはサインアップ直後からAPIにアクセスできる（再ログイン不要）。これはUX上重要: サインアップ → 即ダッシュボードに遷移できる。

セッションコントローラー（ログイン/ログアウト）

backend/app/controllers/api/v1/auth/sessions_controller.rb
module Api
  module V1
    module Auth
      class SessionsController < ApplicationController
        def create
          user = User.find_by(email: params[:user][:email])

          if user&.valid_password?(params[:user][:password])
            # ログインごとにトークンを再生成（セキュリティ向上）
            user.update!(authentication_token: SecureRandom.hex(32))

            render json: {
              user: user_response(user),
              token: user.authentication_token
            }
          else
            render json: { error: 'Invalid email or password' }, status: :unauthorized
          end
        end

        def destroy
          authenticate_user!
          # トークンを無効化（ログアウト）
          current_user.update!(authentication_token: SecureRandom.hex(32))
          render json: { message: 'Logged out successfully' }
        end

        private

        def user_response(user)
          {
            id: user.id,
            email: user.email,
            display_name: user.display_name,
            profile_image: user.profile_image
          }
        end
      end
    end
  end
end
ログイン時にトークン再生成する理由: もし古いトークンが漏洩していた場合、ログインするたびに無効化される。これにより「盗まれたトークンがいつまでも有効」というリスクを軽減する。

ログアウト時もトークン再生成: トークンをnullにするのではなく新しい値に置き換える。これにより、旧トークンが確実に無効化される。valid_password? はDeviseが提供するメソッドで、bcryptでハッシュ比較してくれる。

2-6. フロントエンド: APIクライアント React

認証トークンの保存・送信を一元管理する fetch ラッパー:

frontend/src/lib/api.ts
const BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:3000/api/v1';

function getToken(): string | null {
  return localStorage.getItem('auth-token');
}

export function setToken(token: string): void {
  localStorage.setItem('auth-token', token);
}

export function clearToken(): void {
  localStorage.removeItem('auth-token');
}

export async function api<T>(path: string, options: RequestInit = {}): Promise<T> {
  const token = getToken();
  const headers: Record<string, string> = {
    'Content-Type': 'application/json',
    ...options.headers as Record<string, string>,
  };

  if (token) {
    headers['Authorization'] = `Bearer ${token}`;
  }

  const response = await fetch(`${BASE_URL}${path}`, { ...options, headers });

  if (response.status === 401) {
    clearToken();
    window.location.href = '/sign-in';
    throw new Error('Unauthorized');
  }

  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    throw new Error(body.error || body.errors?.join(', ') || `API Error: ${response.status}`);
  }

  return response.json();
}
401が返ってきたら自動的にトークンを破棄しログインページへリダイレクトする。これにより、トークン期限切れやサーバー側でのトークン無効化に対して、どのページにいても一貫した挙動になる。

2-7. フロントエンド: AuthContext & AuthGuard React

frontend/src/contexts/AuthContext.tsx（ポイントのみ）
// TanStack Query の useCurrentUser を使い、認証状態を管理
// ログイン成功 → setToken() → invalidateQueries(['currentUser'])
// ログアウト → clearToken() → invalidateQueries(['currentUser'])

export const useCurrentUser = () => {
  return useQuery({
    queryKey: ['currentUser'],
    queryFn: () => api<User>('/user'),
    retry: false,  // 401なら即失敗（リトライしない）
    staleTime: 5 * 60 * 1000,  // 5分間はキャッシュ利用
  });
};

2-8. 動作確認チェックリスト

  1. サインアップ → トークンがlocalStorageに保存される
  2. ログイン → 新しいトークンでlocalStorageが更新される
  3. 認証済みで /api/v1/user が200を返す
  4. 無効トークンで401が返る
  5. ログアウト → 旧トークンが無効化される
  6. フロントエンドで未認証状態だと /dashboard にアクセスできずリダイレクトされる
