Step 5: ランディングページ & 仕上げ

所要時間: 1日 | Next.js固有コードの置換パターン集 + エラーハンドリング

このStepのゴール

Next.js固有のAPIを全てReact標準に置き換え、ランディングページを移植し、エラーハンドリングとレスポンシブ対応を完了させる。

5-1. 置換パターン一覧 React

Next.js React + Vite
"use client" → 削除（全てクライアントコンポーネント）
import Image from 'next/image' → <img> タグ
import Link from 'next/link' → import { Link } from 'react-router'
useRouter() from next/navigation → useNavigate() from react-router
useSearchParams() from next/navigation → useSearchParams() from react-router
usePathname() → useLocation().pathname
router.push('/path') → navigate('/path')
redirect('/path') (Server) → navigate('/path', { replace: true })
Server Actions ("use server") → TanStack Query useMutation
revalidatePath() → queryClient.invalidateQueries()
async Server Components → useQuery + Suspense/Loading状態
useAuth() from @clerk/nextjs → useCurrentUser() (自作フック)
<UserButton /> (Clerk) → 自作 <UserMenu />
metadata export (SEO) → 不要（SPAではサーバーレンダリングしない）
手動 useQuery / useMutation → $api.useQuery / $api.useMutation（OpenAPI自動生成）

5-2. next/image → img 置換 React

Before

import Image from 'next/image'

<Image
  src="/hero.png"
  alt="Hero"
  width={600}
  height={400}
  priority
/>

After

<img
  src="/hero.png"
  alt="Hero"
  width={600}
  height={400}
  loading="eager"  // priority相当
  className="w-full h-auto"
/>
next/image が提供していた最適化（WebP変換、レスポンシブ srcset、遅延読み込み）はVite SPAでは使えない。loading="lazy" でブラウザネイティブの遅延読み込みは利用可能。画像最適化が必要なら、ビルド時に vite-plugin-image-optimizer を使うか、CDN側（CloudFront）で画像変換する。

5-3. next/link → React Router Link React

Before

import Link from 'next/link'

<Link href="/dashboard">
  ダッシュボード
</Link>

After

import { Link } from 'react-router'

<Link to="/dashboard">
  ダッシュボード
</Link>

主な違い: href → to に変更するだけ。

5-4. ルーティング（useRouter → useNavigate） React

Before

import { useRouter } from 'next/navigation'

const router = useRouter()
router.push('/dashboard')
router.replace('/sign-in')
router.back()

After

import { useNavigate } from 'react-router'

const navigate = useNavigate()
navigate('/dashboard')
navigate('/sign-in', { replace: true })
navigate(-1)  // back

5-5. エラーバウンダリ React

Next.js の error.tsx に相当する機能を React Router の errorElement で実現:

// ルート定義
{
  path: '/dashboard',
  element: <DashboardPage />,
  errorElement: <ErrorPage />,  // このルート以下でのエラーをキャッチ
}

// ErrorPage.tsx
import { useRouteError, isRouteErrorResponse } from 'react-router'

function ErrorPage() {
  const error = useRouteError()

  if (isRouteErrorResponse(error)) {
    return <div>{error.status}: {error.statusText}</div>
  }

  return <div>予期しないエラーが発生しました</div>
}

5-6. TanStack Query のグローバルエラーハンドリング React

// main.tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      retry: (failureCount, error) => {
        // 401/403はリトライしない
        if (error.message.includes('401') || error.message.includes('403')) {
          return false;
        }
        return failureCount < 3;
      },
      staleTime: 1000 * 60,  // 1分間はキャッシュを新鮮とみなす
    },
    mutations: {
      onError: (error) => {
        toast.error(error.message);  // sonner で通知
      },
    },
  },
});
staleTime: 60000 — デフォルトではコンポーネントがマウントされるたびにAPIを再呼び出しする。1分間はキャッシュを使うことで、ページ遷移→戻る時の不要なリクエストを削減する。UXとしてもデータが即座に表示されて快適。

  1. ランディングページが正しく表示される（画像・リンク・レイアウト）

  6. モバイル表示でサイドバーが正しく開閉する
  7. npm run build がエラーなく完了する
